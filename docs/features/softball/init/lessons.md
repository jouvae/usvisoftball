| L-init-01 | 2026-07-09 | T3 | process | The `.opencode` ECA tooling + `AGENTS.md`/`.claude/rules/data.md` assume a Go/gRPC/SpiceDB/GORM monorepo (Jouvae); this repo is standalone greenfield Next.js. Applying those technical rules verbatim would be wrong. | Treat inherited platform rules as *reference*, not law, on this repo. Re-baseline conventions for the actual Next.js stack during `/plan`. Only *process* lessons (ECA phases, entities registry) transfer. | open |
| L-init-02 | 2026-07-09 | T3 | process | `/conceptualize`'s Step 0 preflight and its entire backend loop (`go-tester`, `go-implementer`, Dorothy `/api/v1` proxy, `gormClient`, `go test -tags testmode`) assume the Jouvae Go monorepo. On this repo none of it exists, so following the command literally would have produced fictional steps. | Adapt the command's *principles* (live-first, smallest visible slice, real data, every slice ships a test, self-verify by observing, one slice + hard stop) and drop its Jouvae *mechanics*. For a full-Next.js repo the "verification of record" is the Playwright e2e alone; there is no backend integration test to write. | open |
| L-init-03 | 2026-07-09 | T3 | tooling | `nextjs-tester` and `nextjs-implementer` both list `DESIGN.md` as required reading, and the `design-system` skill points at it — but it did not exist in this repo. Left unaddressed, both agents would have invented Jouvae conventions (`src/components/`, `useApis`, `serverApiClient`, tests under `clients/web/tests/e2e/`) that have no referent here. | Before spawning either `nextjs-*` agent on a fresh repo, have `architect` author `DESIGN.md` first, and explicitly brief every agent that their inherited rules file targets a different stack. Re-baselining conventions cannot wait for `/plan` — the agents read them at Conceptualize time. | open |
| L-init-04 | 2026-07-09 | T3 | tooling | Next.js 16 enforces **one dev server per project directory** via a lock at `.next/dev/lock`, with no CLI flag or env var to relocate `distDir` or disable it. The dev server started during preflight silently blocked Playwright's `webServer` from booting on :3100 — the failure surfaced as `Another next dev server is already running`, not as a port conflict. | Do not leave a preflight dev server running before a Playwright run; let `webServer` own its server. Identify strays by `readlink /proc/<pid>/cwd`, never by port alone — a `next-server` on :3000 here belongs to `/home/tony/code/inspirations`, an unrelated project. | open |
| L-init-05 | 2026-07-09 | T3 | tooling | Playwright intermittently failed with a Next.js "Manifest file is empty" runtime overlay (surfacing as `global-error.js … React Client Manifest`), which looks like an implementation bug but is corrupt/partial Turbopack `.next/dev` manifest state accumulated across dev-server restarts. | When e2e failures appear non-deterministic or the app renders an error overlay instead of the page, `rm -rf .next` and re-run before debugging component code. Always confirm a green run from a clean `.next`. | open |
| L-init-06 | 2026-07-31 | T3 | process | An *absence/denial* scenario ("contributor cannot publish", "unauthenticated cannot reach /admin", "draft never leaks") passes **vacuously** if the capability it denies doesn't exist yet — a green test proving nothing. Seen repeatedly: the auth gate would pass by redirecting *everyone*; "contributor cannot publish" is meaningless until editor-publish exists. | Sequence a negative/absence scenario **after** the positive capability it denies, and prove the barrier **empirically out-of-band with a real role JWT** (not structurally). Build "gate + real login" not "gate only"; build editor-publish (06) before contributor-cannot-publish (07). Make the anti-tautology assertion explicit (e.g. omit a redundant `status='published'` filter so a broken RLS policy fails the test instead of hiding). | open |
| L-init-07 | 2026-07-31 | T3 | process | The project's **Supabase subdomain stopped resolving mid-session** (free-tier pause/delete), halting every build step (migrations, seeds, real-auth e2e, RLS probes). Conceptualize forbids mocking the backend, so the work genuinely could not proceed. | Verify backend reachability at phase start; on loss, **diagnose general-vs-project-specific DNS** (control hosts resolve, the project host doesn't → it's the project) and surface it as a **first-class human blocker** (the human owns the project), never mock/fake past it. Author unverified code in parallel **only with explicit human opt-in**, and re-verify every line against the restored backend before marking anything done. | open |
| L-init-08 | 2026-07-31 | T3 | tooling | A subagent's green cannot be trusted: its **dev server dies with the task**, and its **sandbox may lack egress to the live backend** (the tester couldn't reach Supabase during the outage; implementers sometimes could psql, sometimes not). Inferring "it works" from a subagent report violates verify-by-observing. | The orchestrator owns verification: apply migrations itself, restart its **own** server from a clean `.next`, run the full suite, drive the **real browser**, and prove RLS/data properties with **out-of-band REST probes using real-role JWTs** (never the service key on the assertion path; service key only to seed/read the fixture). Identify servers by `readlink /proc/<pid>/cwd`, never by port. | open |
| L-init-09 | 2026-07-31 | T3 | training | A **prefix-match** cleanup (`title LIKE '[e2e]%'`) silently misses a marker the generator splices **mid-value** (the AI stub built `"Federation report: [e2e-007] <uuid>"`); an ad-hoc verify driver leaked a row that a same-pattern leftover-check also missed. | When a generator embeds a unique test marker **inside** a larger string, cleanup + queue filters must use a **contains-match** (`%marker%`), and the baseline must be re-confirmed by **total row count**, not by re-querying with the same (faulty) marker pattern. QA caught this as a contract fix (MINOR-1); encode it in the spec, not just the driver. | open |
